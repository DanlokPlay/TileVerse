# Полное описание функционала приложения TileVerse

## 1. Назначение приложения

**TileVerse** — это однопользовательское приложение-головоломка в жанре пазла, разработанное на Unity. Пользователь выбирает изображение, задаёт размер разрезания на фрагменты и собирает исходную картинку из отдельных частей на игровом поле.

Приложение ориентировано на простой и понятный игровой сценарий:

1. запуск приложения;
2. переход из главного меню к настройке пазла;
3. выбор изображения;
4. настройка количества фрагментов;
5. запуск игры;
6. ручная сборка изображения путём перетаскивания деталей;
7. завершение пазла и возврат в меню.

---

## 2. Общая структура проекта

В текущем проекте используется **одна основная сцена**: `Assets/Scenes/SampleScene.unity`.

Приложение построено вокруг одного центрального управляющего компонента:

- `PuzzleGameController` — управляет экранами интерфейса, запуском игры, генерацией пазла, логикой перемещения деталей, стыковкой и завершением партии.

Дополнительные скрипты отвечают за:

- генерацию формы фрагментов пазла;
- создание текстур и спрайтов деталей;
- хранение моделей данных;
- объединение соединённых деталей в группы;
- обработку наведения и перетаскивания;
- выбор пользовательского изображения через файловый диалог.

---

## 3. Главное меню

После запуска приложения отображается **главное меню**.

Доступные действия:

- кнопка **«Начать игру»** переводит пользователя на экран настройки пазла;
- кнопка **«Выход»** закрывает приложение;
- при запуске в Unity Editor кнопка выхода завершает Play Mode, а в собранном приложении вызывает `Application.Quit()`.

Главное меню служит стартовой точкой взаимодействия и позволяет перейти к следующему этапу без дополнительных настроек.

---

## 4. Экран настройки пазла

После нажатия кнопки старта открывается **экран настройки**, на котором пользователь подготавливает будущую партию.

### 4.1. Выбор изображения

Пользователь может выбрать источник изображения для пазла двумя способами:

- использовать одно из **двух встроенных изображений**;
- загрузить **собственное изображение** с устройства.

Встроенные изображения:

- `Горы`;
- `Поляна`.

Если по какой-то причине встроенные графические файлы отсутствуют, код проекта умеет автоматически создать два запасных процедурных изображения:

- закатный пейзаж;
- геометрическую композицию.

### 4.2. Загрузка собственного изображения

Для пользовательского изображения реализован файловый выбор:

- в Unity Editor используется стандартное окно `OpenFilePanel`;
- в Windows Standalone используется нативный системный диалог выбора файла;
- поддерживаются форматы `PNG`, `JPG`, `JPEG`.

После загрузки изображение:

- считывается из файла;
- преобразуется в читаемую текстуру Unity;
- подготавливается для дальнейшей нарезки на фрагменты;
- становится текущим выбранным изображением.

### 4.3. Предпросмотр изображения

На экране настройки отображается **предпросмотр выбранной картинки**.

Система автоматически подгоняет размер предпросмотра под контейнер интерфейса с сохранением пропорций. Это позволяет корректно отображать как квадратные, так и прямоугольные изображения.

### 4.4. Настройка сетки разрезания

Пользователь может задать сложность пазла через два ползунка:

- количество фрагментов по горизонтали;
- количество фрагментов по вертикали.

Ограничения:

- минимальное значение: `2`;
- максимальное значение: `8`.

Таким образом, приложение поддерживает размерности от **2x2** до **8x8**.

Текущие значения ползунков сразу отображаются рядом с ними, чтобы пользователь видел итоговую конфигурацию до начала игры.

### 4.5. Запуск и возврат

На экране настройки доступны:

- кнопка **«Начать»** — запускает генерацию и сборку пазла;
- кнопка **«Назад»** — возвращает пользователя в главное меню.

---

## 5. Игровой экран

После подтверждения настроек открывается **игровой экран**, на котором происходит сборка пазла.

Основные элементы экрана:

- область размещения деталей;
- область игрового поля;
- подложка-подсказка с исходным изображением;
- текстовая подсказка по текущему состоянию игры;
- кнопка возврата в меню.

### 5.1. Область игрового поля

В центре интерфейса располагается поле, куда пользователь собирает изображение. Внутри этой области показывается ориентир — полупрозрачная подложка с выбранной картинкой. Она помогает понимать, как должен выглядеть итоговый результат.

### 5.2. Область исходных деталей

Для хранения и разбрасывания деталей используется отдельная область `Source Area`. Именно там или вокруг игрового поля располагаются стартовые позиции кусочков, в зависимости от активной конфигурации интерфейса.

### 5.3. Подсказки игроку

В игре используется текстовая строка подсказки, которая сообщает:

- что нужно сначала настроить игру;
- какой размер сетки выбран;
- что требуется перетаскивать детали и собирать изображение;
- что пазл полностью собран.

---

## 6. Генерация пазла

После запуска партии приложение автоматически формирует набор фрагментов пазла на основе выбранного изображения и заданной сетки.

### 6.1. Разрезание изображения

Исходная картинка делится на прямоугольные области согласно числу строк и столбцов. Для каждого элемента вычисляются точные границы фрагмента в пикселях.

### 6.2. Формирование формы деталей

В отличие от обычного разрезания на прямоугольники, приложение создаёт **пазловые формы с выступами и выемками**.

Особенности реализации:

- у каждой детали есть стороны `Top`, `Right`, `Bottom`, `Left`;
- крайние детали по границе пазла имеют ровную внешнюю сторону;
- внутренние стороны получают случайный тип соединения;
- если у одной детали справа выступ, у соседней слева автоматически формируется соответствующая выемка;
- то же правило действует для верхних и нижних соседей.

Это обеспечивает правильную геометрию стыковки и делает форму деталей логически согласованной.

### 6.3. Создание визуального изображения детали

Для каждой детали:

- строится маска формы;
- из исходной текстуры выбираются соответствующие пиксели;
- вне формы детали фон делается прозрачным;
- по краям добавляется лёгкое затемнение, чтобы визуально выделить границы элемента;
- создаётся отдельный `Sprite` с плотной формой (`SpriteMeshType.Tight`).

В результате каждая деталь визуально выглядит как самостоятельный пазловый фрагмент, а не как простой прямоугольник.

---

## 7. Размещение деталей в начале игры

После генерации все части получают стартовые позиции.

Система размещения учитывает:

- размер игрового поля;
- размеры самих деталей;
- безопасное расстояние между фрагментами;
- запрет на стартовое наложение деталей на центральную область сборки.

Если свободного места недостаточно, используется запасной алгоритм размещения по окружности вокруг зоны сборки.

Стартовые позиции дополнительно перемешиваются, чтобы порядок элементов не был предсказуемым.

---

## 8. Управление деталями

Каждый пазловый фрагмент является интерактивным объектом интерфейса.

Поддерживаемые действия пользователя:

- наведение курсора;
- начало перетаскивания;
- перемещение детали;
- отпускание детали.

### 8.1. Перетаскивание

При начале перетаскивания:

- активируется группа, к которой принадлежит фрагмент;
- выбранная группа выводится поверх остальных;
- для всей группы фиксируется единое перемещение относительно указателя.

Во время движения:

- считается смещение курсора;
- на это же смещение двигаются все элементы группы.

Это важно, потому что после соединения нескольких деталей пользователь перемещает уже не одну часть, а целый собранный блок.

### 8.2. Наведение курсора

При наведении на деталь или группу её масштаб увеличивается до полного размера, чтобы элемент было удобнее рассмотреть и захватить.

Когда курсор уходит, размер группы возвращается к обычному состоянию, если пользователь в этот момент её не перетаскивает.

---

## 9. Механика соединения деталей

Ключевая игровая функция приложения — автоматическое соединение элементов при правильном сближении.

### 9.1. Прилипание к правильной позиции

После отпускания группы система проверяет, находится ли хотя бы одна из её деталей достаточно близко к своей точной позиции на поле.

Если расстояние меньше заданного порога:

- вся группа автоматически сдвигается в корректное место;
- создаётся эффект «магнитного» прилипания.

### 9.2. Слияние с соседними деталями

После этого приложение проверяет, может ли текущая группа соединиться с другой группой.

Условия соединения:

- сравниваются только реальные соседи по сетке;
- вычисляется ожидаемое взаимное положение деталей;
- если отклонение по координатам невелико, группы автоматически совмещаются.

После успешного совпадения:

- одна группа поглощает другую;
- все элементы теперь считаются единым блоком;
- собранный блок можно двигать целиком.

### 9.3. Повторная стабилизация

После каждого отпускания система несколько раз подряд повторяет:

- попытку привязки к полю;
- попытку объединения с соседями.

Это сделано для того, чтобы цепочки совпадений срабатывали за одно действие пользователя, а не требовали много лишних перемещений.

---

## 10. Проверка завершения игры

Партия считается завершённой, когда одновременно выполняются два условия:

- все детали объединены в одну общую группу;
- каждая деталь находится практически точно в своей правильной позиции.

После завершения:

- внутренний флаг `puzzleCompleted` блокирует дальнейшее обычное взаимодействие;
- текст подсказки меняется на сообщение о том, что пазл собран;
- итоговая группа переводится в полный масштаб.

---

## 11. Возврат в меню и очистка состояния

Из игрового режима пользователь может вернуться в меню.

При возврате приложение:

- удаляет все созданные игровые объекты деталей;
- уничтожает временные спрайты и текстуры, созданные для фрагментов;
- очищает списки активных деталей и групп;
- сбрасывает флаг завершения;
- восстанавливает исходную компоновку интерфейса;
- показывает главное меню.

Это позволяет начинать новую партию без перезапуска приложения.

---

## 12. Работа с изображениями и памятью

В проекте реализована отдельная подготовка текстур для стабильной работы.

### 12.1. Подготовка исходного изображения

Перед использованием изображение:

- при необходимости масштабируется;
- ограничивается максимальным размером примерно до `1600` пикселей по большей стороне;
- переводится в формат `RGBA32`;
- получает линейную фильтрацию и режим `Clamp`.

Такой подход снижает нагрузку на память и делает работу с пользовательскими изображениями более предсказуемой.

### 12.2. Очистка ресурсов

При завершении игры или уничтожении объекта контроллера:

- временные текстуры пользовательского изображения удаляются;
- все созданные текстуры деталей также удаляются;
- очищаются ссылки на встроенные изображения, подготовленные во время выполнения.

Это уменьшает риск накопления неосвобождённых ресурсов в памяти.

---

## 13. Технические особенности реализации

Приложение использует следующие основные технологии Unity:

- `UGUI` для интерфейса;
- `Input System` для работы с UI-вводом;
- `URP` как базовый рендер-пайплайн;
- стандартные `Canvas`, `Button`, `Slider`, `Text`, `RawImage`, `Image`.

Дополнительно в проекте:

- автоматически создаётся `EventSystem`, если он отсутствует на сцене;
- присутствует иконка приложения;
- в настройках проекта указано имя продукта `TileVerse`;
- используется фиксированный оконный режим без изменения размера окна;
- стартовое разрешение для standalone-конфигурации задано как `1024x768`.

---

## 14. Платформенные особенности

По текущей реализации приложение в первую очередь ориентировано на **Unity Editor** и **Windows Standalone**.

Это связано с тем, что загрузка пользовательского изображения реализована так:

- в редакторе — через `EditorUtility.OpenFilePanel`;
- в Windows-сборке — через WinAPI-диалог `GetOpenFileName`;
- на прочих платформах метод выбора файла возвращает пустой путь.

Следовательно:

- встроенные изображения доступны везде;
- выбор собственного изображения гарантированно реализован для Editor и Windows;
- на других платформах этот сценарий в текущем виде не активен.

---

## 15. Что реально умеет приложение в текущем виде

На основе анализа сцены и кода проект в текущем состоянии поддерживает следующий завершённый пользовательский функционал:

- запуск приложения и переход между экранами;
- выбор одного из встроенных изображений;
- загрузку пользовательской картинки с устройства на Windows и в редакторе;
- предпросмотр выбранного изображения;
- выбор сложности пазла через раздельную настройку строк и столбцов;
- генерацию пазла с классическими соединительными выступами и выемками;
- случайное размещение деталей перед началом сборки;
- ручное перетаскивание деталей мышью;
- автоматическое соединение соседних фрагментов;
- магнитное прилипание к корректной позиции на поле;
- проверку полного завершения пазла;
- возврат из игры в меню и запуск новой партии.

---

## 16. Ограничения текущей версии

В проекте **не реализованы** следующие функции:

- сохранение и загрузка прогресса;
- система очков, таймер или статистика партии;
- несколько игровых режимов;
- выбор уровня сложности через готовые пресеты;
- звуковые эффекты и музыкальное сопровождение;
- анимации завершения;
- многопользовательский режим;
- адаптированная мобильная система выбора изображения;
- набор нескольких сцен с отдельными разделами приложения.

Также по текущей конфигурации сцены видно, что некоторые текстовые ссылки контроллера не привязаны:

- `setupStatusText`;
- `completionText`.

Это означает, что соответствующая логика сообщений в коде предусмотрена, но часть текстовых уведомлений может не отображаться в интерфейсе, пока эти поля не будут подключены в инспекторе Unity.

---

## 17. Итог

TileVerse представляет собой законченное пазл-приложение с базовым, но полноценным игровым циклом: от выбора изображения и настройки сетки до интерактивной сборки пазла с автоматическим соединением деталей. Основной акцент сделан на простом управлении, наглядном интерфейсе и алгоритмической генерации фрагментов на основе выбранной картинки.

Для учебного отчёта приложение можно характеризовать как **односценную 2D-головоломку с пользовательской загрузкой изображений, настройкой сложности и автоматизированной логикой стыковки пазловых элементов**.
