# Режимы окна и доступность деталей

Решение согласовано 22 октября 2026 года. Уточнение пользователя: возвращать деталь от края только после отпускания мыши. Подсветка относится к детали пазла, контур экрана не добавляется.

## Поведение

В существующем окне настроек появляется список «Отображение» с вариантами в указанном порядке:

1. Полный экран — Unity FullScreenWindow.
2. Эксклюзивный полный экран — ExclusiveFullScreen.
3. Оконный на весь экран — MaximizedWindow.
4. Оконный — Windowed.

Выбор применяется сразу и не перезапускает пазл. При открытии меню показывается актуальный режим. Последний размер обычного окна сохраняется в течение сеанса. Переключение режима сохраняет соединение и позиции деталей через существующую адаптивную компоновку. В Editor выбор проверяется без изменения окна самого редактора.

Документация Unity 6000.3 описывает MaximizedWindow как развёрнутое окно Windows с заголовком: https://docs.unity3d.com/6000.3/Documentation/ScriptReference/FullScreenMode.MaximizedWindow.html.

Существующее увеличение при наведении сохраняется. Контур детали становится немного отчётливее и светлее только при наведении или захвате. Подсветка соединённой группы согласована для всех её деталей. Нажатия по прозрачным участкам по-прежнему проходят сквозь них. Постоянная рамка экрана не создаётся.

При перетаскивании деталь и группа продолжают свободно следовать за точкой захвата в обеих координатах. При отпускании, если видимая доля площади фрагмента меньше 5%, весь фрагмент одним смещением отодвигается внутрь, чтобы была доступна заметная часть. Для больших и разреженных групп видимость оценивается по сумме прямоугольников непрозрачного содержимого отдельных деталей, без пустого общего охватывающего прямоугольника. Возвращается минимум 20% доступной площади наиболее подходящей детали и не менее 32 экранных пикселей по затронутой координате, насколько позволяет окно. Масштаб и стыки сохраняются. Если видно не менее 5%, положение после отпускания не меняется.

## Реализация

Отдельный небольшой компонент отвечает за режимы окна. PuzzleSettingsView связывает выпадающий список с этим компонентом, а редакторский установщик создаёт и сериализует новую строку интерфейса. Применение режима не связано с подтверждением сброса фото и сетки.

PuzzlePieceView хранит границы непрозрачного содержимого, рассчитанные один раз из геометрии спрайта, и параметры контурной подсветки. PuzzleGameController определяет видимость и возвращает группу при отпускании. Расчёт не читает пиксели и не создаёт массивы на каждом кадре.

## Проверка

- Четыре подписанных режима, обратное отображение выбора, применение без пересоздания деталей.
- Подсветка при входе и её снятие при выходе, сохранение масштаба и прозрачного попадания мышью.
- Одиночные детали и группы у четырёх сторон и в углах: 6% видимости сохраняются, 4% вызывают возврат.
- Во время захвата движение остаётся свободным, возврат выполняется только при отпускании.
- Размер и взаимные положения группы не меняются; высокие фрагменты сохраняют движение по обеим осям.
- Регрессия: существующие проверки генерации, настроек, рамки, завершения и видео.
- Режимы Windows проверяются в отдельной сборке, если её запуск доступен; Editor не выдаётся за проверку нативного полноэкранного переключения.

## Границы работы

Не добавляются выбор монитора, разрешения, частоты обновления, обводка экрана и сохранение партии. Пользовательские изменения ProjectSettings, включая версию 1.0.2 и исходный полноэкранный режим, сохраняются.

## Краткий план

1. Добавить компонент отображения, список TMP и обновить сцену.
2. Настроить подсветку и заменить проверку полной невидимости порогом 95% при отпускании.
3. Дополнить проверки граничных случаев, запустить регрессию и обновить README.
